# Мобильный вход и пати

Дата: 8 сентября 2026.

Повторная проверка, найденный дефект офлайн-PWA и подтверждение реального Steam Guard: [отчёт от 8 сентября](mobile-verification-2026-09-08.md). Он также уточняет текущую сборку APK и фактическую версию эмулятора.

## Вход

- Кнопки Steam сохраняют безопасный внутренний адрес возврата, включая приглашение и фильтры поиска.
- На Android сохраняется внешний адрес сервера `10.0.2.2:3002`, в браузере стенда `localhost:3002`. В публичной конфигурации используется `APP_URL`.
- Начало входа создаёт десятиминутное состояние и отдельный секрет браузера в HttpOnly cookie. В существующей таблице `VerificationToken` хранятся только их хеши и срок действия. Callback атомарно погашает запись, проверяет состояние браузера и точный подписанный `return_to`. Повторный или просроченный callback не создаёт сессию.
- Отмена, истечение времени и сбой проверки открывают `/login` с объяснением и повторным входом к исходному действию.
- Cookie сессии использует Secure на HTTPS. Локальный HTTP в APK не теряет сессию только из-за production-режима Node.
- Запрос проверки Steam ограничен 12 секундами, необязательное получение профиля 5 секундами.
- Service Worker не перехватывает переходы авторизации.
- В Android сетевой сбой на странице Steam открывает нативный экран повторного входа поверх WebView. Системная ошибка Chromium не может заменить его; кнопки работают без сети и без JavaScript страницы. Экран и адрес повтора сохраняются при пересоздании Activity.

При исходном воспроизведении форма Steam открылась. Отдельно воспроизведён сетевой сбой; новая сборка восстанавливает вход после возвращения сети. Полный вход с реальным паролем/Steam Guard не выполнялся.

## Правила Пати

Пати использует существующую сущность `Team`: тот же состав затем подаётся на кубок. Это состав на платформе, не чтение группы из запущенного клиента Dota 2.

1. Соло-игрок нажимает «Пригласить в пати», видит окно и подтверждает отправку. Создаётся группа с ним как лидером. Повторные одновременные приглашения не создают несколько групп.
2. Уже состоящий в группе игрок использует выбранное пати. Приглашение не меняет лидера.
3. До принятия видны пригласивший, лидер, текущие участники и число мест `N/5`.
4. Участник может пригласить друга напрямую или создать URL. Вступивший всегда получает роль `member`, не капитана или заместителя.
5. Окно обновляет состав каждые 3 секунды, свёрнутая панель каждые 10 секунд; также при возвращении к приложению. Скрытые вкладки не опрашиваются.
6. После вступления снимается соло-заявка LFG. Лидер и пригласивший получают уведомление.
7. Только лидер исключает других. Участник может выйти. Лидера нельзя исключить или вывести из основы обычной операцией.

## Ссылки И Ограничения

- URL действует 24 часа. Прямое приглашение действует 7 дней.
- В базе хранится SHA-256 токена ссылки, а не сам токен.
- Принятие требует Steam-сессии; GET только показывает состав, не добавляет игрока автоматически.
- Лидер может отозвать ссылки. Исключение игрока отзывает старые URL группы, чтобы исключённый не вернулся по той же ссылке.
- Выход пригласившего делает его старые ссылки и прямые приглашения недействительными.
- Поддерживается копирование URL и в локальном HTTP WebView, где нет современного Clipboard API.
- Показанный URL привязан к конкретному пати: при переключении группы ссылка от прежней группы скрывается.
- Изменяющие запросы проверяют Origin и авторизацию. Создание приглашений и ссылок ограничено по частоте.
- Проверка вместимости, добавление участника, уведомления и аудит выполняются в транзакции с блокировкой строки команды.
- Если двое одновременно принимают приглашения на последнее место, вступает один. Второй получает 409; его приглашение остаётся ожидающим.

## Кубки

- Заявку подаёт лидер. Сетку создаёт организатор кубка, а не любой лидер пати.
- Проверяются пять подтверждённых Steam-игроков и конфликты участия за другую команду в том же кубке.
- Изменение ещё не зафиксированного состава возвращает одобренную заявку на рассмотрение и обновляет снимок игроков. Место в очереди ожидания сохраняется.
- Check-in повторно проверяет актуальных игроков и фиксирует их снимок под той же блокировкой состава.
- После check-in и попадания в сетку обычные вступления, выходы и исключения запрещены. Для замены остаётся существующий турнирный процесс.

## Файлы И Запуск

- Основная логика: `server/party/service.ts`.
- Мобильное окно: `components/players/PartyPanel.tsx`.
- Миграция: `20260907180000_party_invite_links` (применена к локальному стенду).
- Стенд: `http://localhost:3002/party-search`.
- APK: `android/app/build/outputs/apk/debug/app-debug.apk`.

```powershell
npm.cmd test
$env:AEGIS_E2E_PARTY = '1'
$env:AEGIS_E2E_ADMIN = '1'
npx.cmd playwright test
```

E2E использует отдельные временные аккаунты, команды и кубки в локальной базе на `5434`. После теста удаляются только созданные им записи. В тестах этап одобрения заявок задаётся фикстурой; регистрация, check-in и создание сетки проходят через реальные API.

Для нативной проверки отладочный WebView должен быть перенаправлен ADB на `127.0.0.1:9223`:

```powershell
node scripts/verify-android-auth.mjs
node scripts/verify-android-party.mjs
```

Первый сценарий открывает настоящую форму Steam без ввода учётных данных и трижды имитирует отсутствие сети. Второй использует временные тестовые сессии: участник копирует ссылку, переключает две группы, друг вступает, счётчик в APK автоматически меняется с 2/5 на 3/5. Тестовые сессии и данные удаляются.

## Результаты Проверок

- `npm.cmd run check`: Prisma, TypeScript, 69 файлов / 251 модульный тест, ESLint без ошибок. Есть 12 предупреждений в `Header`, `TeamCatalog`, `TournamentExplorer`.
- Общий Playwright-прогон: 25 проверок успешно, 5 повторных проверок админки пропущены конфигурацией. Проверены Chromium/WebKit, экраны 360, 375, 393, 430 и 1440 px, а также URL/local/S3 в редакторе оформления.
- После последних изменений: ещё 4 сценария пати и возврата Steam успешно на Android-small и iPhone/WebKit. Финальные артефакты: `test-results-party-final`.
- При одном повторном прогоне возникла ошибка записи трассировки при закрытии браузера; все игровые шаги прошли. Прогон повторён с отдельной папкой артефактов. Очистка тестов теперь удаляет временные данные и при ошибке закрытия браузера; оставшиеся записи конкретного прерванного прогона также удалены.
- `npm.cmd run build`: успешно. На Windows с Docker-адресами из `.env` во время сборки есть предупреждения недоступности `postgres2`/`redis2`. Работающий стенд проверялся внутри Docker на порту 3002.
- Android `assembleDebug lintDebug`: успешно. Обновление APK установлено на эмулятор API 36.
- В финальном APK настоящая форма Steam открыта без ввода пароля; три последовательных сбоя сети и повтора входа прошли. Экран проверен через UIAutomator, кнопка повтора через реальные касания ADB. Скриншоты: `android/build/auth-steam-form.png`, `android/build/auth-network-retry.png`.
- В том же APK повторно прошли копирование URL участником, переключение двух пати без чужой ссылки и живое обновление состава 2/5 -> 3/5. Скриншот: `android/build/party-member-live.png`. Приложение возвращено на гостевую главную, временные данные удалены. Ошибок AndroidRuntime в журнале нет; `/party-search` отвечает HTTP 200.
- SHA-256 APK: `A43C22CFBDE806F5429E369B50B62E9E167B815B296D6CF6A3EA54341C4FA3F2`.

Debug APK настроен на адрес сервера в эмуляторе. Для реального телефона нужна сборка с доступным ему адресом, для распространения публичный HTTPS-домен и release-подпись. Физический iPhone/Safari в эту проверку не входит.
