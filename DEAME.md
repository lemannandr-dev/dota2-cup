# Aegis Arena — как устроен проект и куда его вести

Это рабочая карта продукта, а не маркетинговый текст. Цель файла — чтобы любой, кто садится развивать платформу, понимал: что уже живое, что недоделано, и в каком порядке чинить.

План следующих этапов с критериями готовности: [PLAN.md](PLAN.md).

Репозиторий: `media-game-cup`. Публичное имя: **Aegis Arena**. Стек: Next.js 15, React 19, Prisma, PostgreSQL, Redis, MinIO, Docker.

Локальный стек, с которым сейчас работаем: `docker-compose.second.yml` → сайт на `http://localhost:3002`.

---

## 1. Что это за продукт

Aegis Arena — турнирная платформа для Dota 2.

Игрок заходит через Steam, собирает пятёрку, ищет пати, подаёт заявку на турнир, проходит чек-ин, играет сетку. Организатор ведёт заявки, судит споры, платит призовые через внутренний ledger. Сайт показывает ранг и историю из OpenDota и, если получилось, **официальные уровни героев Dota Plus** из реплеев.

Продукт крутится вокруг трёх обещаний:

1. **Турнир как процесс**, а не лендинг: заявка → одобрение → чек-ин → готовность → матч → двойной счёт → выплата.
2. **Steam без пароля.** Логин — OpenID. Пароль Steam, Guard и userdata на сайт не принимаем.
3. **Цифры Dota не выдумываем.** Ранг и матчи — OpenDota. Уровни Plus — только `hero_xp` из реплея. Гильдейские очки — только если GC-воркер реально прочитал ответ координатора.

## 2. Как это устроено сейчас

```
Браузер
  │
  ├─ Next.js (web) ──────── Prisma ──── PostgreSQL
  │     │                      │
  │     ├─ Redis (кэш OpenDota, pub/sub)
  │     ├─ MinIO / S3 (хранилище, почти не используется в UI)
  │     └─ HTTP /emit ──► realtime (Socket.IO, порт 3003)
  │
  ├─ Helper на ПК игрока (PowerShell + Python)
  │     └─ одноразовый код ──► POST /api/dota-sync/submit
  │
  └─ gc-worker (отдельный контейнер, Steam-бот)
        └─ пока только логин в Steam; protobuf гильдий ещё нет
```

### Вход

Рабочий путь — **Steam OpenID** (`/api/auth/steam` → cookie `aegis_session`). После входа редирект в `/profile/{id}`.

Рядом лежит **NextAuth** (email/пароль + Discord). В интерфейсе основной поток — Steam. Два контура сессий путают: middleware смотрит только `aegis_session`.

### Турниры

- Форматы: single и double elimination.
- Заявка команды, ревью организатора, чек-ин, ready-handshake в день старта.
- Счёт: обе команды шлют репорт; при расхождении — спор.
- Можно привязать Dota match id и сверить состав через OpenDota.
- Призовые: резерв → выплата в баланс пользователя (копейки в `Int`).
- Фоновый тик в `instrumentation.ts` раз в минуту двигает статусы REGISTRATION → CHECK_IN → FINISHED.

### Сообщество

- Команды, инвайты, вызовы (challenges). Каталоги `/teams`, `/players`, `/tournaments`, `/party-search` — карточки и меню, не широкие таблицы.
- Поиск игроков и LFG: `/party-search` — анкета и приглашение в команду. В списке только те, кто уже заходил через Steam. «Онлайн» = заход на арену за 15 минут, не клиент Dota. После принятия инвайта — ссылки на команду и турниры.
- Уведомления в колокольчике.
- Живое обновление турнирной страницы через Socket.IO.

### Dota-профиль и герои

- OpenDota: ранг, винрейт, топ героев, последние матчи. На `/profile` это вкладки и меню (правый клик / ⋯), не одна длинная лента.
- Каталог `/heroes`: сетка как в клиенте.
- Официальный Plus: публичные реплеи Valve (кнопка «Подтянуть уровни как в игре») и локальные `.dem` через helper.
- Бейдж Plus рисуем **только** если есть официальный XP. Оценку «50 XP за игру» больше не маскируем под уровень из клиента.

### Гильдии

Таблицы `DotaGuild*` и внутренний `POST /api/internal/dota-guilds/snapshot` есть. Воркер логинится в Steam и включает Dota 2, но **адаптера protobuf гильдии ещё нет**. Выдумывать очки и состав нельзя.

## 5. Что требует доработки

### Продукт и UX

1. **Два лица сайта.** Лендинг обещает турниры, а игрок после Steam попадает в профиль с гильдией и helper. Навигация «Аналитика» ведёт в профиль. Нужен один понятный домашний экран после логина: турниры / моя команда / герои.
2. **Два способа входа.** `/login` и `/register` рядом со Steam. Для турнирной Dota-платформы Steam должен быть единственным боевым входом. Email/Discord — либо довести и связать с тем же User, либо убрать из UI.
3. **Dota Plus не полный.** Публичный реплей живёт у Valve коротко. Старые герои с 1–5 играми остаются без бейджа. Helper требует Python и PowerShell — для части игроков это стена.
4. **Гильдия в профиле почти пустая.** Пока нет GC-адаптера, блок только путает.
5. **Видео, хайлайты, ачивки** есть в Prisma и нигде в приложении. Либо вырезать из схемы, либо сделать один вертикальный кусок (хотя бы загрузка VOD после матча).
6. **i18next подключён и не используется.** Интерфейс весь на русском, `NEXT_PUBLIC_SUPPORTED_LOCALES` ни на что не влияет.

### Турнирный движок

7. **Тик живёт внутри процесса Next.** Второй инстанс web = два тика. Нужен один worker/cron, не `setInterval` в `instrumentation.ts`.
8. **Нет автоматического старта LIVE и генерации сетки по таймеру.** Чек-ин закрывается, но «нажать bracket» всё ещё руками.
9. **Double elimination и BYE** покрыты тестами частично. Неявка одного капитана после дедлайна закрывается автотехом. Если молчат оба — ждём судью.
10. **Верификация OpenDota** не закрывает кастомки, лобби без парса и приватный профиль.
11. ~~Капитан vs состав.~~ Замена после check-in есть; сыгранная пара хранит свою пятёрку в `Match.rosterA/B`.

### Dota Plus и реплеи

12. Синхронизация реплеев идёт **в HTTP-запросе до 12 минут**. Нужна очередь (Redis/Bull) и статус «идёт разбор матча N».
13. На Windows Docker **не видит правки файлов** (том `.next`, нет inotify). После UI-правок часто нужен `docker restart media-game-cup-web-3`. Для разработки — polling watch или без изолированного `.next`.
14. ~~Helper и public разъедутся~~ — `npm run helper:copy`, версия в `/helper-version.json`.
15. `.edem` не читаем — это ограничение Valve, не баг. В инструкции это должно оставаться явным.

### Инфраструктура и качество

16. **Два compose.** `docker-compose.yml` (порт 3001) и `docker-compose.second.yml` (3002). Легко поднять не тот стек. Один каноничный dev-файл.
17. **Тестов мало:** регистрация, сетка, репорт. Нет тестов на Steam-сессию, Plus-merge, payout, ready-handshake, sync submit.
18. **Секреты в `.env` для dev** — нормально локально; в README не светить ключи. Steam API key не должен попадать в git.
19. **MinIO** поднят, в пользовательских сценариях почти не задействован (логотипы команд, скрины споров).
20. **GC-воркер** без protobuf — snapshot без `source: gc` + `payload.gcMessage` отвергается, блок гильдии скрыт.
21. **Realtime** отдельным контейнером. Если процесс на хосте займёт 3003, Docker-контейнер не стартует. Это уже ловили.

### Безопасность и доверие

22. Смена роли пишет `ROLE_CHANGED`. TOTP орга обязателен, если `prizePool > 0`.
23. IDOR на заявку / инвайт / challenge / счёт чужой пары закрыт политикой. `GET /api/admin/bonus-codes` больше не без авторизации.
24. Публичные реплеи качаем с Valve CDN — это легитимные свои матчи, но нужен лимит на пользователя, чтобы не долбить CDN.

## 7. Как развивать, не разъехавшись

Правила, которые уже окупились на этом репозитории:

1. **Сначала турнирная правда, потом витрина.** Сетка, счёт, выплата важнее красивого лендинга.
2. **Источник цифры всегда явный.** OpenDota / реплей / клиент / оценка. Игрок не должен гадать, почему Зевс 27, а Силенсер без бейджа.
3. **Один стек для разработки.** Сейчас это `docker-compose.second.yml`, порт 3002, realtime 3003, postgres 5434.
4. **После правки UI на Windows** проверять, что контейнер отдал новый бандл. Если классы в DOM старые — рестарт `media-game-cup-web-3`.
5. **Helper и сервер менять вместе.** Схема `heroes[]` в submit — контракт. Сломал поле — сломал уровни у всех, кто синкает.
6. **Не плодить мёртвые модели.** Новая таблица — только вместе со страницей или API, которые её читают.

### Как поднять стенд

```bash
cp .env.example .env
docker compose -f docker-compose.second.yml up -d --build
```

Сайт: `http://localhost:3002`  
Realtime health: `http://localhost:3003/health`  
Postgres: `localhost:5434`  
Сиды: `docker exec -w /app media-game-cup-web-3 npm run prisma:seed`

Realtime на хосте (`npm run realtime`) и контейнер `media-game-cup-realtime-3` не запускать одновременно — порт 3003 один.

### Как проверять фичу

- Турнир: создать → заявка → approve → чек-ин → bracket → два репорта → выплата.
- Plus: залогиненный Steam → `/heroes` → «Подтянуть уровни как в игре» → бейдж только у тех, чей `.dem` ещё на Valve.
- Helper: профиль → код → `DotaSyncHelper.ps1` → `yes` → в базе строки `DotaHeroProgress`.

## 8. Короткий рассказ «где мы»

Проект уже не макет. Можно собрать команду, объявить турнир и довести его до счёта. Можно показать игроку его настоящий Plus по свежим каткам.

Слабое место не «нет идей», а **склейка**: два входа, два compose, тик внутри Next, Plus в длинном запросе, гильдия без данных, мёртвые куски схемы. Если следующие месяцы закрыть этот контур, Aegis Arena из «площадки с Dota-обвязкой» станет площадкой, которой можно отдать реальный приз и не краснеть за цифры на карточках героев.

Дальше развиваем так: один вход, один дев-стенд, очередь синка, железный турнирный тик, честные данные. Всё остальное — после.

## 9. Как сделана первая волна (проверено в коде)

Это не план «на потом», а то, что уже лежит в репозитории.

### Steam как боевой вход

- `/register` сразу уводит на `/api/auth/steam`. Игрок не создаёт email-аккаунт.
- `/login` сверху показывает кнопку Steam. Форма email оставлена только как служебный контур и не выдаёт турнирные права.
- После успешного OpenID callback редирект на `/home`, не в профиль.
- Залогиненный заход на `/` тоже уходит на `/home`.
- Гостевой `/` больше не рисует `lib/mock.ts`: турниры, пары и игроки с арены. Аналитика на лендинге — только пояснение источников, без выдуманного win rate.

### Домашний экран `/home`

Сначала стол пар: заявки, где пользователь в составе, следующий шаг (`lib/match-day.ts`: отметка, готовность, счёт, спор, рекап). После закрытой пары — счёт, +16/−12 и почему нет бейджа Plus. Эфир и Plus открываются из меню (ПКМ / ⋯), не лентой. Если сессии нет — редирект на лендинг.

### Лобби пары

Капитан на доске пишет имя лобби, пароль, сервер и голосовой. Состав и соперник видят это на `/home` и на карточке турнира. Чужой пароль не видит. Это не GSI — просто как пяти людям зайти в одну катку.

### Судья

Организатор на карточке ищет судью по имени человека, который уже заходил на арену через Steam (SteamID64 тоже принимается). Тот становится судьёй штаба и получает колокольчик. «Отправить судье» пишет сопернику и штабу, ссылка ведёт на пару. Открытые споры — блок на карточке и на `/home` у штаба. Это не отдельный человек «из воздуха».

### Ожидание игроков

На столе `/tournaments/{id}/watch`, в оверлее OBS и на доске пары — десять слотов с аватарками. Зелёные: команда подтвердила готовность. Жёлтые пульсируют: команда ещё не ответила. Это не accept в клиенте Dota и не поигроковый ready.

### Стол эфира

При создании турнира орга указывает Twitch/YouTube стола, второй язык, Dota TV, лобби и задержку. Это `Tournament.broadcast`, не строка в правилах. Картинка — embed канала. Онлайн-счёт — серия с арены. Net worth / GSI катки нет и не рисуем. OBS: `/overlay/tournaments/{id}`. Зритель: `/tournaments/{id}/watch`.

### Шапка

Пункты «Главная / Герои / Профиль» рисуются на сервере из cookie, не после `/api/me`. Иначе залогиненный сначала видит короткое гостевое меню, потом пилюля прыгает.

### Дедлайн счёта

У открытой пары есть `reportDeadlineAt` (3 часа). Если к сроку счёт сдал только один капитан, тик ставит TECHNICAL с этим счётом. Два молчуна и спор — не трогаем.

### Замена после отметки

Капитан меняет одного из пяти на подтверждённого запасного команды. Пока пара не началась (нет репорта и спора). Уже закрытые пары не переписываются: перед свапом их состав копируется в `Match.rosterA` / `rosterB`.

### Коридор до пятёрки

Заявка на кубок считает Steam, не просто «подтверждённых». С `/teams` и карточки турнира капитан попадает в `/party-search?teamId=&tournamentId=`. Приглашение без Steam или в уже полную пятёрку сервер отклоняет. После принятия игрок видит Steam N/5 и кубок. На `/home` один шаг: добрать состав, **заявить 5/5** или действие пары. Колокольчик чек-ина и MATCH_SOON ведёт на `/home`. Если `prizeStatus` не CONFIRMED, сумма на карточке помечена «фонд не зарезервирован».

### Закрытый кубок и сирота

После `FINISHED` колонки заявок — «Сыграли / 1 место / 2 место / выбыли», не жёлтое «ждут день турнира». Стендовые кубки с заголовком «Прогон приза…» помечены отдельно от объявленных. Черновик всегда пишет `createdById`. Если у живого кубка орга не было, `claimOrphanTournament` вешает владельца и штаб OWNER; `CONFIRMED` без транзакции эскроу сбрасывается в `UNCONFIRMED`, деньги не печатаем.

### Доска пары и колокольчик

На карточке турнира капитан видит состав, готовность, сдаёт счёт или открывает спор. Закрытая пара показывает рекап: счёт, +16/−12, кто идёт дальше, и что бейдж Plus за вход на матч не ставится. Организатор назначает судью по имени с арены (`TournamentStaff.REFEREE`). После финала выплата только с предпросмотра и подтверждения, и только из зарезервированного фонда. «Отправить судье» пишет сопернику и штабу; открытые споры видны на `/home` у судьи. Судья пишет решение и может поставить техпоражение.

### Очередь Plus без 5-минутного POST

1. Браузер жмёт кнопку → `POST /api/dota-sync/public-replays`.
2. Сервер пишет job `queued` в Redis (`plus-sync:job:{userId}`, TTL 20 мин). Если Redis недоступен, тот же объект живёт в памяти процесса.
3. Ответ сразу `202`. Разбор реплеев идёт в `after()` — после ответа.
4. Кнопка каждые 2.5 с делает `GET` того же URL и пишет «Сейчас качаю Zeus — реплей N из M». Бейдж только с официального XP, не +50 за игру.
5. Политика в `lib/plus-sync-policy.ts`: нельзя запустить второй job, пока `queued`/`running`; после `done` пауза 10 минут; после `error` можно сразу.

Политику покрывает `tests/plus-sync-policy.test.ts`.

### Пустая гильдия скрыта

Блок «Гильдия Dota 2» на профиле рендерится только если есть `guild.lastSyncedAt`. Пока GC не прислал настоящий снимок, игрок не видит заглушку «ещё не синхронизировано».

### Watch в Docker

У `web2` в `docker-compose.second.yml` стоят `WATCHPACK_POLLING` и `CHOKIDAR_USEPOLLING`, чтобы правки с Windows чаще доходили без рестарта контейнера. Рестарт **не** стирает `.next` — иначе Next заново компилирует весь сайт и падает с `ENOMEM`, а `/home` отвечает 500. Чистая сборка: `docker compose -f docker-compose.second.yml exec web2 rm -rf .next/*` и рестарт.
